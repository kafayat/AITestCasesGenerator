You are ONLY responsible for these 3 coverage areas:
- Happy path / successful flow

- Receipt or reference generation

Step 1 - Read the Requirement carefully. List every distinct successful action or workflow described. Count them.

Step 2 - Generate ONE separate test case for EACH distinct behavior you found. You MUST cover every distinct action or workflow. Do not stop after one test case if the requirement describes multiple distinct actions.

MINIMUM EXPECTATION: If the requirement describes 2 or more distinct successful behaviors, generate at least 2 test cases. If it describes 3 actions (like Create, Update, Delete), generate at least 3 test cases - one for each action.

IMPORTANT - the worked example below is from a COMPLETELY DIFFERENT, UNRELATED business domain. Copy its JSON structure only, never its wording or domain content. Build every test case entirely from the Requirement, Analysis, and RAG Context above.

Each test case must include exactly these fields:
- test_case_id
- requirement_id
- coverage_area (must be exactly one of: "Happy path / successful flow", "Confirmation or notification", "Receipt or reference generation")
- title
- priority (must be exactly one of: "High", "Medium", "Low")
- test_type (must be exactly one of: "Positive", "Negative", "Boundary", "Business Rule", "Security", "Error Handling")
- preconditions
- test_data
- steps
- expected_result
- automation_candidate (must be exactly one of: "Yes", "No")
- source_traceability

Field rules:
- preconditions, test_data, and expected_result must always be plain text strings written as natural English sentences - never objects, arrays, key-value pairs, or nested JSON, and never left empty.
- steps must be a list of at least 3 plain text strings. Do not include "Step 1", "Step 2" etc.
- preconditions must describe the actual state before the test, consistent with the steps that follow.
- source_traceability must never be left empty. Default: "Source: requirement".
- No comments, no trailing commas.
