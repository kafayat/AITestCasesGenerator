Objective:

Generate comprehensive enterprise-grade test cases using coverage-driven testing principles.

The goal is not to generate a fixed number of test cases.

The goal is to generate enough test cases to achieve complete behavioural, business rule, validation, risk, and traceability coverage.

Coverage Principles:

* Prioritize coverage over quantity.
* Generate as many test cases as necessary to achieve complete requirement coverage.
* Cover every identified business rule.
* Cover every validation rule.
* Cover every user flow.
* Cover every critical risk area.
* Generate separate test cases for distinct behaviours.
* Do not combine unrelated validations into one test case.
* Generate positive and negative coverage where applicable.
* Generate edge-case and boundary coverage where limits exist.
* Include failure and recovery scenarios where applicable.
* Include security and sensitive data handling scenarios where applicable.
* Include data integrity validation where applicable.
* Include audit, tracking, confirmation, notification, receipt, reference number, and logging validation where applicable.

Coverage Areas To Consider:

* Happy path / successful flow
* Alternate flow
* Invalid input
* Missing mandatory data
* Business rule validation
* Boundary condition
* Edge case
* Duplicate processing
* Concurrency scenario
* Failed transaction
* System failure
* Service unavailable
* Integration failure
* Retry and recovery
* Confirmation message
* Notification generation
* Receipt generation
* Reference number generation
* Security validation
* Authorization validation
* Authentication validation
* Sensitive data handling
* Data integrity
* Data persistence
* Audit logging
* Error handling
* Exception handling
* User experience validation

RAG Usage Rules:

* Use RAG context to identify additional business rules, validations, workflows, domain knowledge, constraints, and enterprise testing patterns.
* Generate additional test cases when RAG context introduces new behaviours.
* Use sample test cases only as style guidance.
* Do not copy sample test cases.
* Do not limit generation to the structure of sample test cases.
* Prefer requirement content over sample test cases when conflicts exist.

Traceability Rules:

* Every test case must map to at least one requirement, business rule, validation, or RAG source.
* source_traceability must clearly indicate where the test case originated from.
* If source file information exists, include the file name.
* If multiple sources contribute, list all relevant sources.

Automation Candidate Rules:

Set automation_candidate to:

* Yes = Stable, repeatable, deterministic scenario
* Partial = Requires setup, external dependency, or mixed validation
* No = Requires manual verification, usability assessment, or human judgement

Priority Rules:

Critical:

* Production blocking failures
* Security issues
* Financial impact
* Regulatory impact
* Data loss

High:

* Core business functionality
* Mandatory workflows
* Business rule validation

Medium:

* Secondary functionality
* Alternate flows

Low:

* Cosmetic behaviour
* Minor usability checks
