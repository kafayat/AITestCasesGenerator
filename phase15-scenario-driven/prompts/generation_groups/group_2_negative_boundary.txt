You are ONLY responsible for these 3 coverage areas:
- Invalid input
- Missing mandatory data
- Boundary condition

Step 1 - Read the Requirement carefully. List every distinct invalid input scenario, every mandatory field that could be left empty, and every boundary condition implied by the requirement. Count them.

Step 2 - Generate ONE separate test case for EACH distinct scenario you found.

MINIMUM EXPECTATION: If the requirement describes multiple mandatory fields, generate at least one test case per mandatory field type (e.g. missing email, missing name, missing address). If it describes fields with options (like a dropdown), generate at least one invalid/empty selection test case. Do not generate only one test case when the requirement clearly has multiple distinct negative scenarios.

IMPORTANT - the worked example below is from a COMPLETELY DIFFERENT, UNRELATED business domain. Copy its JSON structure only, never its wording or domain content.

Each test case must include exactly these fields:
- test_case_id
- requirement_id
- coverage_area (must be exactly one of: "Invalid input", "Missing mandatory data", "Boundary condition")
- title
- priority (must be exactly one of: "High", "Medium", "Low")
- test_type (must be exactly one of: "Positive", "Negative", "Boundary", "Business Rule", "Security", "Error Handling")
- preconditions
- test_data
- steps
- expected_result
- automation_candidate (must be exactly one of: "Yes", "No")
- source_traceability

Field rules:
- preconditions, test_data, and expected_result must always be plain text strings - never objects, arrays, or nested JSON, and never left empty.
- steps must be a list of at least 3 plain text strings. Do not include "Step 1", "Step 2" etc.
- Every test case in this group must use genuinely invalid, missing, or boundary-violating data. Expected result must commit to a single definite outcome - never a conditional "if/else" statement.
- source_traceability must never be left empty. Default: "Source: requirement".
- No comments, no trailing commas.
